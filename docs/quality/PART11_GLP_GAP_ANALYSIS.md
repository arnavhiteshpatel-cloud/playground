> **Status: DRAFT. OsteoQuant is not compliant with 21 CFR Part 11 or GLP, is not validated, and no regulator has reviewed it.**
> Part 11 and Part 58 do not apply to OsteoQuant's current research use. This document benchmarks the desktop product against them to plan readiness for customers who may later want to use it in regulated work. Compliance would be a property of a customer's validated, procedurally controlled use of the system, never of the software alone.

## 1. Legend
- **Technical control:** what the desktop software does today (FS reference).
- **Status:**
  - **TESTED**: implemented and an automated engineering test asserts the behaviour (matrix VERIFIED). Engineering tests are not OQ execution.
  - **PARTIAL**: implemented in part, or implemented without a test that asserts it.
  - **GAP**: not implemented.
- **Owner:** V = OsteoQuant (supplier); U = user organisation (test facility).

## 6. Remaining gaps (prioritised)
1. **No executed verification or validation.** IQ/OQ/PQ templates exist (v0.2) but none has been run; the dossier is engineering evidence only. Physical-data evidence for the graft/new-bone separation and for the advisor's decisions is missing.
2. **Attributability on a shared workstation.** No user administration in the desktop, no idle lock, desktop re-authentication bypasses lockout, admin role not separated.
3. **Record integrity against OS-level editing.** Study tables are outside the hash chain; no anchor export/import; no on-demand integrity check; validation-record file unprotected.
4. **Records management.** Retention not enforced; no project backup/restore verification, archive export with manifest, audit export or JSON/label-map export in the desktop.
5. **Operational checks.** No QC gate, ROI-verified gate, SAP lock, unblinding in the desktop, post-unblinding flag or review state machine.
6. **Quality system basics.** Document control, training records, independent QA, incident/CAPA, periodic review, e-signature policy, supplier/quality-agreement pack.

## 7. Recommended next steps
1. Fix the desktop re-authentication defect and add user administration and an idle lock (engineering; small).
2. Bring study tables under the hash chain (or a signed per-record hash), add anchor export and an integrity check (engineering).
3. Execute IQ and OQ on one reference workstation; record failures as deviations.
4. Stand up minimal QMS procedures (document control, training, change control, CAPA).
5. Execute PQ-05 (measurement-support correctness on physical phantoms) before any statement about graft/new-bone performance.
