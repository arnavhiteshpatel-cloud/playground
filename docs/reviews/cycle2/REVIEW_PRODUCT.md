# OsteoQuant Desktop: product review, cycle 2

**Perspectives:**
- micro-CT analyst and study director (UX);
- QA / test engineer;
- security engineer;
- software architect.

**Scope:**
- fixes claimed for cycle 1 in `docs/reviews/cycle1/REVIEW_UX.md` (Response table), `REVIEW_ML_ARCH.md` + `RESPONSE.md`, `docs/qa/DEFECTS_FOUND.md`, `docs/security/SECURITY_REVIEW_GEN2.md` and `docs/quality/ENGINEERING_VALIDATION_DOSSIER.md` §11;

**Date:** 2026-11-27. The working tree was reviewed as found; no code was changed.

## Method

- **Code reading** of these areas:
  - `osteoquant/desktop/` (project, services, blinding, lock, jobs, main window, dialogs, reports, review/audit views, support);
  - `osteoquant/study/db.py`, `audit/log.py`, `licensing/`, `io/readers.py`, `ml/{train,runtime,validation_records}.py`, `pipeline.py`, `advisor/integration.py`, `api/bundle.py`;
  - the shipped `models/registry.json` and model cards.
- **Regression probes** (not committed; each was run on a throw-away project in a temporary directory, with `OQ_MODEL_DIR` pointed at a temporary folder so that `models/` was never touched). Every probe used the public service functions that the desktop UI calls. The Evidence column describes each probe precisely enough to repeat it.
- **Headless UI** (`QT_QPA_PLATFORM=offscreen`):
  - a demo project built with `desktop.demo.build_demo_project`;
  - a `MainWindow` driven as in `desktop/screenshots.py`;
  - screenshots in `docs/reviews/cycle2/screens/` (`c2_01` … `c2_05`).
- **Test runs:**
  - `python3 -m pytest -q tests/desktop` (run once): **82 passed** in 112 s.
  - Targeted re-run of the regression tests named for QA-001…021 and G2-01…12 (selection by name over `test_io_destructive`, `test_safe_archive`, `test_audit_properties`, `test_security_gen2`, `test_stats_reference`, `test_segmentation_metrics`, `test_ml_phantom`, `test_io_properties`, `test_properties_science`, `test_transforms_roi`, `test_store_api_workflows`): **71 passed**.
  - `ruff check --select F401` on the QA-025 files: clean.

**Severity scale:**
- **High**: can mislead a sign-off, mis-attribute data or defeat a stated control.
- **Medium**: a control works only partly, or data or attribution can be degraded under realistic use.
- **Low**: hardening or hygiene.
