Security & data protection

Your scans stay on your computer

OsteoQuant Desktop is local-first. Scans, segmentations, results, reports and the audit trail live in a project folder you choose. The application sends no telemetry, checks for no updates and makes no network connections. Licence-file signatures are checked offline.

The application does not encrypt project folders. Use your operating system’s disk encryption, keep projects on access-controlled drives and include them in your backups. Backup and restore steps: docs/user/DATA_PROTECTION.md.

Network

What leaves the computer

  • No telemetry, crash reporting or usage analytics.
  • No update checks and no licence server: licence files carry an Ed25519 signature checked against a public key built into the application.
  • No cloud processing: analysis runs in the same process as the user interface.

Data leave the computer only when you export them (CSV, PDF, screenshots) or copy the project folder.

Optional web prototype

The local server, if you use it

The earlier browser-based prototype (osteoquant serve) is kept as an optional automation interface. It binds to 127.0.0.1 by default and prints a warning if bound to another interface. It is not needed for the desktop application.

The security review below covers its upload handling; open low-severity items relate mainly to it.

Integrity

Changes are recorded, alterations are detectable

Hash-chained audit trail

Rows are only inserted; database triggers reject updates and deletes. Each row’s SHA-256 hash covers the previous row’s hash. Verify chain finds the first altered event. Record the head hash elsewhere so that truncation is also detectable.

Provenance of inputs

Each imported scan is hashed (SHA-256) and duplicates are detected. Chunked scan stores are checked against their recorded hash, so missing or modified chunks are reported instead of silently read as empty.

Revisions, not overwrites

Corrections create a new segmentation revision with the user, reason and per-class voxel changes. Signatures record their meaning and the hash of the signed labels.

Access control

Per-project users and roles

Each project has its own users. The audit trail attributes every action to the signed-in user.

Roles
Administrator, analyst, reviewer, viewer. Authors cannot approve their own segmentations.
Passwords
At least 10 characters with an upper-case letter and a digit; stored as salted scrypt hashes.
Lockout
Five failed sign-in attempts lock the account for 15 minutes. Signatures require password re-entry; failed re-entries are recorded in the audit trail.
Blinding
Blinded review mode hides group names, animal IDs and file names for every role; blinded studies also hide allocation from non-administrators.

This website

No cookies, no trackers

These pages set no cookies, run no analytics and load no fonts, scripts or images from other servers. The only script toggles the menu on small screens. The contact form is a placeholder and sends nothing.

Pilot data

Before any scan changes hands

No pilot runs today. Pilots are planned only after incorporation, a written data-processing agreement and our first release gate (Gate 1, not met). By default your scans are not used to train models; any adaptation to your material needs your written opt-in, and adapted weights are kept for you alone.
